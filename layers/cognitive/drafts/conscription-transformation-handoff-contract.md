# Conscription Transformation and Handoff Contract

## Status

Draft completion increment. Conscription is recruitment. No live packaging or deployment.

## Native Responsibility

Conscription selects an admitted Canonical Persona from an exact eligible set and transforms it into a deployment-medium-specific Operative package. It does not forge, test, admit, activate, or deploy.

## Required Inputs

- exact admitted Persona identity and version;
- exact suitability/search assessment;
- authorized selection criteria and tie behavior;
- target medium and technical contract;
- model, tool, and interface declarations;
- mission-bound constraints;
- required provenance and package lineage.

Missing, stale, conflicting, or non-preservable inputs block conscription.

## Transformation Invariants

The package must preserve:

- professional competence;
- Persona Governance Doctrine;
- applicable Human-Trait Canon limits;
- refusal, evidence, uncertainty, escalation, and stop behavior;
- exact source identities and versions;
- declared deviations forced by the medium.

Conscription must not import source-human identity or grant tools, credentials, or authority by implication.

## Findings

~~~text
OPERATIVE_PACKAGE_CONFORMANT
OPERATIVE_PACKAGE_REFUSED
OPERATIVE_PACKAGE_UNRESOLVED
~~~

A conformant package is not activated, mission-bound, released, or deployed.

## Handoff

Handoff records package identity/version, recipient boundary, source lineage, deviations, acceptance criteria, unresolved limitations, and state transition. Rejection returns to Conscription or the native upstream owner.

## Non-Admissions

No Runtime action, activation, mission execution, credential, provider, deployment, or external effect.
