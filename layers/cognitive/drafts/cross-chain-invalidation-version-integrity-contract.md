# Cross-Chain Invalidation and Version Integrity Contract

## Status

Draft cross-cutting completion increment. No production implementation.

## Purpose

This contract defines when a downstream artifact becomes ineligible after an upstream semantic, evidence, version, capability, or medium change.

## Invalidation Triggers

Reassessment is required after changes to:

- Mission Need or Work Specification;
- Profession Specification or resolution finding;
- Persona Governance Doctrine;
- Human-Trait Canon or EC disposition;
- Persona Specification Candidate;
- Pit test, qualification, or admission evidence;
- Garrison status, inventory view, or suitability criteria;
- selected model, platform, medium, tool declaration, or interface;
- mission constraints;
- package, handoff, or release content.

## Propagation

~~~text
changed source
→ affected direct artifact identified
→ downstream eligibility suspended
→ exact invalidation reason recorded
→ native owner reassessment
→ new version or explicit reaffirmation
→ downstream re-integration / retest / readmission
~~~

No downstream artifact may remain eligible merely because its content appears unchanged.

## Required Record

Each invalidation record preserves:

- source and affected artifact identities/versions;
- changed proposition or condition;
- detection evidence;
- impact scope;
- native owner;
- status: suspended / invalidated / reaffirmed / superseded;
- required reassessment;
- exact successor lineage.

## Cross-Version Rule

Artifacts from different semantic lineages may not be combined unless an explicit compatibility finding identifies the versions, scope, evidence, and owner.

## Non-Admissions

No automatic mutation, approval, Procedure transition, Runtime validator, deployment, credential, or external effect.
