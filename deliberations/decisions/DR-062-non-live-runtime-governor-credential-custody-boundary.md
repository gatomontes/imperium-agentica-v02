# DR-062 — Non-Live Runtime Governor and Credential-Custody Boundary

Recorded bounded implementation-readiness contract. Synthetic evidence only;
this decision authorizes no Runtime operation, credential creation or use,
provider access, activation, deployment, live data, or external effect.

## Contract

Master Mason is the Runtime governor and mechanic. It may inspect declared
Runtime health, start or stop an already-authorized synthetic Runtime session,
pause/resume within an admitted rehearsal, and clear a declared mechanical
fault. It may not choose a mission, alter doctrine, grant authority, select a
provider, access credential storage, activate an Operative, deploy, or produce
an external effect.

Locksmith remains the sole credential custodian and security-persistence
accessor. Credential material is never returned to Master Mason, Muster,
Operatives, mission content, logs, or external providers. A future execution
handoff, if separately admitted, must be opaque, purpose-bound, expiring,
one-use, non-serializable, non-loggable, and revocable. This record does not
admit that handoff.

## Refusal and evidence boundary

Every governor action requires a correlation and authorization reference. A
missing, stale, mismatched, or scope-incompatible reference is refused. A
credential request from any non-Locksmith component is refused. A request that
combines governance with mission judgment, activation, deployment, or provider
access is split or refused rather than elevated by Master Mason.
